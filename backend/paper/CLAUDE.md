# Paper (`backend/paper/`, `backend/routes/paper.py`, `src/lib/paper.ts`)

- **Paper pages are a fixed A4 sheet** (`PAGE_WIDTH`/`PAGE_HEIGHT` = 2100×2970 tenths of a mm in `src/lib/paper.ts`), contain-fit into the viewport with bars on the short axis — never sized to the screen. Ink is stored in that page space and rendered through a **single uniform scale**; the old separate x/y scales were what distorted strokes when the window ratio changed. Pre-A4 rows are converted on read (uniform, centred, so shapes survive) and only rewritten on the next save. The tool palette is a floating panel that snaps to an edge, and it deliberately carries **no transient text**: the save indicator sits in a fixed-width slot because a status that rendered nothing when idle reflowed the toolbar on every autosave.
- **Pictures on a paper page** (`paper_page_images`, `src/lib/paperImages.ts`, `PaperImageLayer.tsx`) — pasted from the clipboard or picked from a file, placed in the same A4 page space as strokes. Three things to know: the picture is **drawn by the canvas** (beneath the ink, so it lands in the snapshot) but **interacted with through a DOM overlay** that only mounts in select mode, which is what keeps handles at 44px and leaves the drawing pointer logic alone; rotation is 90° steps plus a mirror flag, applied about the image's own centre, and resizing scales about that centre so a handle stays under the finger at any angle; and **a locked image is skipped by the hit test entirely** — writing over a photo must not be able to grab it — with the server refusing geometry writes to a locked row too, since an in-flight drag can land after the lock. The stored extension list is closed on purpose: the file is served from our own origin, so an `.svg` would be a script — but the **accepted** list is wider than the stored one, and the two are resolved by `storage.resolve_ext(mime, filename)`, mime first. HEIC/HEIF is transcoded to JPEG at the door (`backend/imaging.py`, the path food and chat photos already took), because HEIC is what the iPad this feature exists for hands over: matching on the filename's extension alone answered `IMG_0042.HEIC` with a 400, which is every picture put on a page from the tablet.
- **A picture that does not reach the server must say so, and stay retryable.** The 400 above was invisible for three compounding reasons, each now closed. The picture kept rendering after the refusal (it is drawn from the blob it was pasted from, which outlives the failed upload), so nothing looked wrong until the page was left. The refusal marked the stored photo `failed`, which the boot sweep in `src/offline/photoQueue.ts` skips forever — right for a file the server will never take, wrong once a build learns to take it, hence `clearFailure`. And a _successful_ upload deletes the device copy while the cache still held the placeholder row the paste wrote (`url: ''`), so the picture blanked out on the next visit exactly as if it had been lost — the add's `onSuccess` now swaps in the row the server returned. The editor shows what this device is still holding for the open paper, with a Retry, rather than leaving the bytes in IndexedDB for nobody.
- **Adding, moving or deleting a picture marks the canvas dirty** (`markDirty` on the canvas handle). The snapshot is only regenerated when the page is dirty, and it is the whole of what the explorer grid and the Journal filmstrip show — so without this a page whose only content is a photo saved, and stayed, a blank sheet.
