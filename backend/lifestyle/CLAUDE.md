# Lifestyle (`backend/routes/lifestyle.py`, `backend/lifestyle/`, `src/components/Lifestyle/`)

Workouts, activity heatmap, tasks, the weekly trends chart, progression charts, daily selfie, calories — one scrollable column. Design record and the decisions the build settled: [docs/lifestyle-tab.md](../../docs/lifestyle-tab.md). Things to know before touching it:

- **The tab absorbed the Tasks view, and DOM order is the phone's stacking order.** `Lifestyle.tsx` orders the column by how often a thing is touched, not by topic: activity + momentum, tasks, workout log, calories | selfie, weight progression. Tasks (`src/components/Tasks/`, daily tasks + to-dos through `/api/tasks`) keeps shortcut scopes 1 and 2; nothing else in the Lifestyle tree registers one.
- **Unfinished daily inputs temporarily outrank that normal order.** Today's selfie, today's body weight, and calories while the running total is below 2,000 render above the activity card. Each returns to its normal location as its shared React Query cache becomes complete; body weight alone leaves/rejoins the Progression card, while the exercise chart stays put.
- **Two pairs share one card**, and the halves render no shell of their own (`CARD` / `CARD_DIVIDER` in `src/components/Lifestyle/card.ts`): activity + momentum (what happened, and which way it's going) and daily tasks + to-dos (both "what am I doing today"). Four small cards read as four separate things.
- **Row-level delete is behind a toggle** in the workout log and the tasks card — the 🗑 reveals the per-row ✕. An always-visible delete sat one mis-tap from destroying a row, beside that row's own click targets. The tasks card has **one** toggle for both its lists (state in `TasksSection`, button rendered in the `DailyTasks` header because that row is the card's top-right corner); two independent ones under a single border would read as one control that half-works.
- **Chores are retired, not renamed.** They were `todos` rows with `list='chores'`; `_merge_chores_into_todos` folded them into `'todo'` and `normalize_list` (`backend/todo_recurrence.py`) still accepts the old name so an offline mutation or a stale chat proposal lands instead of 400ing. `task_events.task_list` keeps the historical value on purpose.
- **`GET /trends` reaches outside lifestyle's own tables** — weekly counts of journal entries and job applications sent (`emails.category='job_application' AND job_status='sent'`). It lives here because the chart does; bucketing is pure in `backend/lifestyle/trends.py`, and **every week is emitted including the zeros**, the opposite of `/heatmap`, because a line that skips its quiet weeks draws a flat trend over a month of nothing.
- **Workout entry is freeform text, parsed in the background** (`backend/ai/workouts.py` → `run_bg`), same pattern as the food/recipe extractors. `raw_text` is never overwritten and `parse_status` tracks the attempt, so a bad parse is retryable via `POST /workouts/<id>/reparse` rather than lost.
- **Exercise names fold one way only** (`backend/lifestyle/exercises.py`): an abbreviation folds onto a known fuller name, but a more specific name starts its own series. Over-merging can't be undone; splitting costs one `POST /exercises/merge`.
- **The workout form mirrors itself to `localStorage`** (`src/lib/workoutDraft.ts`) — logging happens mid-set on a phone, and a backgrounded tab reload would otherwise wipe the textarea. The 300 ms debounce is **flushed on `pagehide` and on a `visibilitychange` to hidden**: a screen lock can tear the page down before the timer fires. Not `beforeunload`, which mobile browsers may skip. The draft is cleared only once the server has the session, so a failed save keeps everything.
- **The activity colours were validated, not chosen by eye** — CVD separation, the normal-vision floor and 3:1 contrast against both surfaces (worst pair ΔE 8.1 deutan, 16.5 normal). Re-run the check if they change; identity is never colour-alone (legend + per-day labels).
- **Five hues is the ceiling, and it was measured.** Fitting `lifting_home` in took a search over OKLCH: 3:1 contrast against a dark surface caps how dark a hue can be and the categorical lightness band caps how light, which leaves the wheel almost full at four. A sixth type will not find a passing hue — it needs a second channel (texture, a mark on the cell), not another colour picked by eye.
- **`ACTIVITY_TYPES` is ordered by priority and inserted into, not appended to** (`backend/lifestyle/activity.py`, mirrored in `src/lib/lifestyle.ts` and `api.ts`'s `ActivityTypeId`). Index _is_ priority, so inserting a type changes which colour a _mixed_ day's box takes — never what was logged. Unknown types sort last so a row from an older build can't break the heatmap.
- **No charting library**: geometry is pure functions in `src/lib/lifestyle.ts`, rendered as inline SVG. `plotSeries` is one series (body weight, one exercise); `plotMultiSeries` projects several onto **one shared y-domain** — never a second axis, which can be scaled to show any relationship you like.
- Selfie images live under `./data/lifestyle/<id>/` (`LIFESTYLE_ROOT`), one per day, never as blobs. **Take selfie goes through the native camera** (a hidden `capture="user"` file input), not `getUserMedia` — the in-page preview was wrong on a tablet. And the history strip is **read-only**: tapping a thumbnail previews it, never deletes. Replacing a day means retaking it that day; removing one is a manual DB edit, because an accidental tap used to destroy a selfie outright.
- **Workout intensity is 1-5 stars, not 1-10 RPE** (`INTENSITY_LABELS` in `src/lib/lifestyle.ts`, `IntensityStars.tsx`): a ten-point scale was too subjective to answer honestly. The five labels are the feature — surface them, and never render the rating as glyphs alone. Old 1-10 values were folded once by `_migrate_workout_intensity_to_stars`, latched on the existence of the `settings.workout_intensity_five_star` column.
- **Bodyweight sets carry `weight: null`**, explicitly required by the parser's JSON schema rather than omitted ("squats 10 10 10 10" is four sets of ten). Anything consuming set weights has to render that as bodyweight and keep it off the weight charts — `Progression.tsx` plots total reps instead.
