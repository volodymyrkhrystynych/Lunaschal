# Writing (`src/components/Writing/`, `backend/routes/writing.py`)

Two-panel layout: left nav (project list + a `WritingNav` with Chapters/Notes/Discussions sections) | full-width center panel that switches on the selected item: chapter → prose editor, note → note editor, discussion → chat view.

**DB tables**: `writing_projects`, `writing_chapters` (ordered by `position`), `writing_context_docs` (typed: `character | outline | worldbuilding | note`). "Notes" in the UI/API are stored in `writing_context_docs` (HTTP paths are `/api/writing/.../notes`; the table name is legacy). Discussions reuse the existing `conversations` + `messages` tables; `conversations.writing_project_id` scopes them to a project, and the general Chat tab filters them out (`writing_project_id IS NULL`). Deleting a project deletes its discussions.

**Chapter/note editors**: plain `<textarea>` (not CodeMirror — prose, not code) with 1.5 s debounced auto-save; chapters add live word count and font-size shortcuts. **Discussions**: full-size chat reusing `/api/chat/stream`; the frontend assembles a `systemPrompt` from the project plus checked notes, and asks for `toolset: 'research'` — the shared offline-first research chain (library first, the web behind `delegate`) and nothing else. A `systemPrompt` alone still means _no_ tools, which is what the voice listener and the nudges need; this is a screen, so it opts back in by name. It deliberately gets no `propose_*`, no `remember` and no recall over the user's own record: there are no confirm cards here, and the life wiki is about the user rather than the piece they are writing. A **Summarize** button distills the transcript into a new note via `backend/ai/writing.py`.

**Discussions send no `conversationId` in the stream request** (a caller-supplied `systemPrompt` takes the inline path in `backend/routes/chat.py`'s `/stream`, same as the voice listener), so — unlike the Chat tab, where the background thread in `backend/delegate/runs.py` writes the assistant row itself — `DiscussionView.tsx` persists the reply _and_ its reasoning trace itself once the stream ends, building `metadata` in the same `{thinking, truncated, timedOut, steps, sources}` shape `parseAgentMeta` expects so a reopened discussion renders the same collapsed `AgentSteps`/`ReasoningBlock` trace the Chat tab does. One consequence worth knowing: a dropped connection loses the reply _and_ its trace, where the Chat tab's background run would have written both to the row regardless. Dictation reuses `useRecorder`, and here it **auto-sends** (a send-style surface, like the Chat tab and fanfic commentary — unlike `IdeaCapture`/`BrainDump`, which append to a textarea), with no correction pass (that's specific to Chat's memory-document/photo context, which a writing discussion has neither of).
